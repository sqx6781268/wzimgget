# WZ 字符串/数据解密与加密形式自动探测

> 对应实现：`wz/key.go`（密钥流）、`wz/detect.go`（探测）、`wz/img.go` Load。

## 1. AES 链式密钥流

WZ 的"加密"本质是 **AES-256-ECB 生成的伪随机密钥流 + 逐字节 XOR**，不是对数据直接 AES 加密。

密钥流生成（与 WzComparerR2 `Wz_CryptoKey.EnsureKeySize` 一致）：

```
aesKey = 13 00 00 00 08 00 00 00 06 00 00 00 B4 00 00 00
         1B 00 00 00 0F 00 00 00 33 00 00 00 52 00 00 00   ; 固定 32 字节

block[0]      = AES-ECB-Encrypt( iv 重复 4 次填满 16 字节 )   ; [iv0..3, iv0..3, iv0..3, iv0..3]
block[n]      = AES-ECB-Encrypt( block[n-1] )                 ; 链式：密文块作为下一个明文块
keys          = block[0] || block[1] || ...                   ; 按需扩长
```

IV（决定"加密形式"）：

| 名称 | IV | 说明 |
| --- | --- | --- |
| KMS | `B9 7D 63 E9` | 韩版 |
| GMS | `4D 23 C7 2B` | 国际版；**样本 Data/*.img 实测全部用 GMS** |
| BMS | `00 00 00 00` | 空 IV：密钥流全 0，等于不加密 |

## 2. 字符串解密两步

对字符串密文缓冲区 `b`（长度字节之后、按长度取出的原始字节）：

```
第 1 步  keystream XOR：  b[i] ^= keys[i]        ; 注意：从密钥流下标 0 开始！
第 2 步  递增掩码 XOR：
        ANSI    : b[i]  ^= byte(0xAA + i)        ; 逐字节
        UTF-16LE: u16[i] ^= ushort(0xAAAA + i)   ; 逐字符（u16 小端）
```

要点/易错：

- **每个字符串缓冲区独立从 keys[0] 开始**（80315 与 master 源码均如此），
  与字符串在文件中的绝对位置无关。
- 长度字节本身**不加密**，标记字节（0x00/0x73/0x01/0x1B）也不加密。
- 长度字节的符号决定编码：负=ANSI(cp1252)，正=UTF-16LE；±128/127 表示后跟 int32 真实长度。
  取反时勿漏 `size = -size`，否则切片越界。
- ANSI 解码对无法映射的字节应**原样保留**（老资源可能有非常规字节），不要转成 U+FFFD。

## 3. Canvas 旧式分块加密数据

像素数据两种形态（首 2 字节判定）：

```
if u16_le(data) 是合法 zlib 头:            ; 0x78 且 (u16 % 31 == 0)，如 78 9C / 78 DA / 78 01
    直接取 zlib 内容
else:                                       ; 旧式加密分块
    循环: len=int32; block=读 len 字节; block ^= keys[0..];   ; 每块也是从下标 0 开始
    拼接后跳过 2 字节 zlib 头再 inflate
```

> 只判断 `78 9C` 会漏掉最高压缩级 `78 DA` 等，务必按 zlib 规范校验头。

## 4. 加密形式自动探测（TryDetectEnc 思路）

WzComparerR2 在打开 img 时先"猜"密钥：读取根类型标记字符串，
用各候选密钥解密，结果落在合法类型名集合内即认定。顺序：`BMS → KMS → GMS`。

移植到独立 .img 的完整策略（本项目实现）：

1. 快速探测：按 BMS/KMS/GMS 依次解根标记（0x73 内联或 0x1B 引用），
   命中合法类型名 → 用该密钥完整解析一次；
2. 兜底：探测失败或解析中途出错 → 回退"逐密钥完整试解析"，
   取解析进度（pos 最深）的部分树返回，保证 dump/尽力提取可用。

好处：正常文件只解析一遍（探测 O(1) 成本），避免整文件重复试解析。

## 5. 密钥流实现的坑（务必检查）

`ensure(n)` 扩容时**必须把旧密钥流复制到新数组前缀**，再从旧长度位置继续链式加密：

```go
newKeys := make([]byte, blocks*16)
if start > 0 { copy(newKeys[:start], k.keys) }   ; 漏掉这行 = 事故
for i := start; i < len(newKeys); i += 16 {
    if i == 0 { 用 iv 块 } else { 用 newKeys[i-16:i] 链式 }
}
```

漏复制的症状极具迷惑性：前 16 字节内的短字符串全部正常，
任何一次扩容之后所有解密结果变乱码（长属性值、其后的引用字符串、乃至整棵树失步），
且不同文件因字符串长度不同表现不一。见 调试经验与踩坑记录.md 案例 1。
