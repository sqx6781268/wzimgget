# Canvas 像素格式与解码

> 对应实现：`wz/canvas.go`、`wz/util.go`。

## 1. form 值的组合规则（旧 v80315 布局）

```
form = compint + sbyte        ; 两个字段相加！
```

常见组合：`0+1=1`、`1+1=2`、`2+1=3`、`512+1=513`、`516+1=517`、`1025+1=1026`、`2049+1=2050`。

## 2. 各 form 的像素布局

| form | 布局 | 解压后字节数 | 解码要点 |
| --- | --- | --- | --- |
| 1 | ARGB4444 | w*h*2 | 每字节拆两个 4bit 半字节，`lo\|lo<<4` 扩展为 8bit；内存序 BGRA |
| 2 | ARGB8888 | w*h*4 | 内存序即 BGRA，直接当 RGBA(PNG 为 RGBA) 处理，仅通道换序 |
| 3 | 4x4 块灰度缩略 | ceil(w/4)*4 * ceil(h/4)*4 / 8 | 每 4x4 块一字节，高低半字节各展开 8 像素 |
| 513 | RGB565 | w*h*2 | 565 → 888 扩展 |
| 517 | 16x16 块 RGB565 缩略 | w*h/128 | 每 16x16 块两字节，需块展开 |
| 1026 | DXT3 | ceil(w/4)*4 * ceil(h/4)*4 | 4x4 块：8 字节显式 alpha（每 2bit 一组，高低半字节 `v\|v<<4`）+ 4 字节颜色插值 |
| 2050 | DXT5 | 同上 | 4x4 块：a0,a1 + 48bit 3bit alpha 索引 + 颜色块 |
| 0 | 未压缩 ARGB8888 | 数据即像素 | 不经 zlib |

DXT 颜色块：c0/c1 两个 RGB565 + 32bit 2bit 索引；`c0>c1` 时 2/3 号色为 2/3 与 1/3 插值，
否则 3 号色为透明黑（3bit 索引与 2bit 索引分属不同字段，**不要混用**）。

## 3. 数据流总览

```
像素数据段（首字节为标志位，实际数据从 +1 开始，长度 bufsize-1）
 ├─ 89 50 4E 47          → 原始 PNG，直接透传
 ├─ 42 4D ("BM")         → 原始 BMP，自行解码
 └─ 其他                  → zlib/分块解密（见 加解密与自动探测.md §3）
      └─ inflate 后按 form 转 BGRA → PNG 编码输出
```

## 4. 空帧/退化帧识别

- `bufsize-1` 仅 2 字节且 w*h 很大：源数据即**空画布**（导出工具产物，如部分抽奖机 NPC），
  无法还原图像。提取器应跳过该候选节点尝试下一个，而不是让整个文件失败。
- 校验 `off+length ≤ 文件大小`，防止坏偏移 panic。

## 5. Go 标准库注意事项

- **Go 1.27 起 `image/bmp` 已从标准库移除**（`not in std` 编译错误）。
  需手写 BMP 解码：支持 24/32bpp 未压缩、自底向上行序（负高度=自顶向下）、
  行 4 字节对齐（stride）。
- 解压用 `compress/flate`（跳过 2 字节 zlib 头后是裸 deflate），或直接用 `compress/zlib`。
- PNG 编码用标准 `image/png` + `image.NRGBA`（内存序 R,G,B,A 逐字节换序即可）。
