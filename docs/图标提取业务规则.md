# 图标提取业务规则（Character / Item / Npc）

> 对应实现：`extract.go`。

## 1. 提取范围

只处理 Data 顶层这三个目录（其余 Effect/Map/Mob/Skill/UI… 整体 SkipDir）：

| 顶层目录 | 内容 | 主图标位置 |
| --- | --- | --- |
| Character | 装备（Cap/Coat/Weapon…）+ 角色部件（Hair/Face） | 装备：`info/icon` 或 `info/iconRaw`；Hair/Face：**无图标节点** |
| Item | 消耗/其他/宠物等 | `info/icon`（部分另有 `info/iconRaw`） |
| Npc | NPC 形象 | 无 info/icon，取动画首帧，如 `stand/0` |

## 2. 图标候选顺序（仿 WzComparerR2）

按序尝试，命中第一个可解码为 Canvas 的路径即停：

```
info/iconRaw → info/icon → info/animatedIcon →
stand0/0 → stand/0 → strike1/0 → swingO1/0 → action/00 → action/stick0 → 0
```

- 每个候选都要经过 **UOL 解析**（属性可能是软链接）；
- 候选**解码失败时继续尝试下一个**（空画布帧、坏数据），全部失败才计为失败；
- `iconRaw` 优先于 `icon`：iconRaw 常是无白底原图，icon 可能带描边底板。

## 3. 输出约定

- 命名：保留原 IMG ID 加 `.png`：`01142538.img` → `01142538.img.png`；
- 目录：镜像 Data 内部结构 → `imgdata/Character/Accessory/01142538.img.png`；
- 默认输出目录 = Data 同级 `imgdata`；
- 单文件模式：`img <xx.img> [-out 路径]` 复用同一候选逻辑，
  默认输出到文件同目录 `<文件名>.img.png`，`-out` 可指定 png 路径或目录；
- 结束打印统计：总数 / 成功 / 无图标 / 失败。

## 4. "无图标"是正常现象，不是 bug

实测 53926 个文件：成功 28504，无图标 25420（其中 Hair 15627 + Face 9611），失败 2。

- Hair/Face 是**穿戴渲染部件**，img 内只有 `default/hairOverHead` 等画布与 `_outlink`，
  没有 `info/icon`——商店图标在 Item.wz 侧，属数据本身如此；
- 若业务需要 Hair/Face 的"代表图"，可另加回退候选：`default/hairOverHead`、`default/face`等
  （当前按"只提取 ico 图标"的需求未做）。

## 5. 性能参考

- 5.4 万文件全量提取约 2~4 分钟（单线程、含 PNG 编码），无需并发即可接受；
- 快速探测密钥（见 加解密与自动探测.md §4）避免了失败文件的重复整树解析。
