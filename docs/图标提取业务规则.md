# 图标提取业务规则（Character / Item / Npc / Mob / Skill / Morph / Reactor）

> 对应实现：`extract.go`。

## 1. 提取范围

只处理 Data 顶层这七个目录（其余 Effect/Map/Sound/UI/Quest/String… 整体 SkipDir）：

| 顶层目录 | 内容 | 主图标位置 |
| --- | --- | --- |
| Character | 装备（Cap/Coat/Weapon…）+ 角色部件（Hair/Face） | 装备：`info/icon` 或 `info/iconRaw`；Hair/Face：默认跳过，`-hairface` 时取 `default/hairOverHead` / `default/face` 代表图 |
| Item | 消耗/其他/宠物等 | 七位单件（如 Pet/5000000.img）：根级 `info/icon`，输出 `5000000.img.png`；**四位组文件**（如 `Etc/0400.img`）：**按内部物品 ID 逐个导出**为 `<物品ID>.img.png`（与组文件同目录，如 `04000000.img.png`），图标位于 `<ID>/info/icon(Raw)`、Special 变体 `<ID>/iconRaw/0` 或 `<ID>/icon` |
| Npc | NPC 形象 | 无 info/icon，取动画首帧，如 `stand/0` |
| Mob | 怪物形象 | 无 info/icon，取动画首帧，如 `stand/0`、`stand0/0` |
| Skill | 技能 | `info/icon`（技能书/分组文件根级即有） |
| Morph | 变身形象 | `stand/0` 首帧；根级落空时下探一层子动作再取一张（如 0098 的 `fly/0` 为 UOL 帧） |
| Reactor | 地图物件 | `0/0`（第一动画组首帧） |

> NPC、怪物等**非物品**资源的图标一般不在 `info/icon` 节点，而在 `stand/0`
> （站立首帧）；物品则相反，几乎都在 `info/icon(Raw)`。
> 实测 Item 全部 463 个文件：357 个根级命中 + 106 个下探一层命中，无遗漏；
> 四位数组文件仅存在于 Item 目录（Character/Npc/Mob 内均为七位单件文件）。

## 2. 图标候选顺序（仿 WzComparerR2）

按序尝试，命中第一个可解码为 Canvas 的路径即停：

```
info/iconRaw → info/icon → info/animatedIcon →
iconRaw → icon → iconRaw/0 → icon/0 →
stand0/0 → stand/0 → strike1/0 → swingO1/0 → action/00 → action/stick0 → 0/0 → 0
```

- `-hairface` 开启时在表尾追加 `default/hairOverHead`、`default/face`
  （Hair/Face 穿戴部件代表图，默认不导出）；

- 每个候选都要经过 **UOL 解析**（属性可能是软链接；UOL 目标缺失时安全返回 nil）；
- 候选**解码失败时继续尝试下一个**（空画布帧、坏数据），全部失败才计为失败；
- `iconRaw` 优先于 `icon`：iconRaw 常是无白底原图，icon 可能带描边底板；
- Item 组文件根级无图标时，**遍历全部子节点逐个导出**（不是只取第一个命中的）。

## 3. 输出约定

- 命名：保留原 IMG ID 加 `.png`：`01142538.img` → `01142538.img.png`；
  Item 组文件按内部物品 ID 命名：`Etc/0400.img` → `Etc/04000000.img.png`（一图一物品，可直接按物品 ID 检索）；
- 目录：镜像 Data 内部结构 → `imgdata/Character/Accessory/01142538.img.png`；
- 默认输出目录 = Data 同级 `imgdata`；
- 单文件模式：`img <xx.img> [-out 路径]` 复用同一候选逻辑，
  默认输出到文件同目录 `<文件名>.img.png`，`-out` 可指定 png 路径或目录；
- 结束打印统计：总数 / 成功 / 无图标 / 失败。

## 4. Store 模式打包（imgdata.zip）

- extract 完成后自动把输出目录打包为 `<输出目录>.zip`（`-nozip` 关闭），
  也可用 `pack <目录> [-out x.zip]` 单独打包；
- 打包用 `zip.Store` 不压缩：PNG 本身已压缩，再 Deflate 收益极低且读取需解压；
  Store 模式按原始字节存取，Go `archive/zip` 打开即按路径随机读取；
- 归档内路径 = 相对源目录的 `/` 分隔路径（`filepath.ToSlash`），与 imgdata 结构一致；
- 价值实测：37110 个文件磁盘占用 131MB（NTFS 4K 簇浪费）→ ZIP 63.3MB
  （= 原始数据 54.4MB + 每条目本地/中央头开销）；
- 图片有增删改时必须重新打包；备份/校验后可删除散文件目录。

## 5. "无图标"是正常现象，不是 bug

实测 56991 个文件（七类域）：成功 30983（共 37110 张图标），无图标 26006（其中 Hair 15627 + Face 9611），失败 2。
Mob 2444 个中约 1865 个有可导出的 stand 首帧，其余为无动画帧的功能性条目。

- Hair/Face 是**穿戴渲染部件**，img 内只有 `default/hairOverHead` 等画布与 `_outlink`，
  没有 `info/icon`——商店图标在 Item.wz 侧，属数据本身如此；
  如需其"代表图"，运行 extract/img 时加 `-hairface` 即可导出
  `default/hairOverHead` / `default/face`（默认关闭）。

## 6. 性能参考

- 5.4 万文件全量提取约 2~4 分钟（单线程、含 PNG 编码），无需并发即可接受；
- 快速探测密钥（见 加解密与自动探测.md §4）避免了失败文件的重复整树解析。
